# M1 文档解析完整链路实施计划

> **面向 AI 代理的工作者：** 必需子技能：使用 `subagent-driven-development` 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 在已有文件上传切片上实现显式 `/parse`、PostgreSQL `task_run`、Celery 调度、内部 MCP `document.ingest`、MinerU 混合解析、DOCX/XLSX 原生解析和统一 Document IR 持久化。

**架构：** FastAPI 领域层在 PostgreSQL 事务中受理解析并创建 `task_run`，提交后才发布 Celery。Worker 通过内部 MCP 调用 `document.ingest`；MCP 调用 Docker 内部自托管 MinerU 处理 PDF/图片，`python-docx` 处理 DOCX，`openpyxl` 处理 XLSX。PostgreSQL 是任务和解析结果唯一事实源，Celery、Redis、MCP 和 MinerU 不承载业务事实。

**技术栈：** Python 3.12、FastAPI、Pydantic v2、SQLAlchemy 2 async、Alembic、PostgreSQL 17、Celery、Redis、官方 Python MCP SDK、内部 MinerU API、`python-docx`、`openpyxl`、pytest、Ruff、mypy。

**安全约束：** 用户曾在聊天中发送 API Key；实现中不得读取、验证、使用、写入代码、日志、测试、记忆或 Git。当前采用内部自托管 MinerU，不需要 API Key，采购文件不发送第三方。生产部署前必须核验 MinerU 自定义许可证、归属披露和商业适用条件。
