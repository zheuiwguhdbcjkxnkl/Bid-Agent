# M1 文档解析部署级联调实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 用分层 Docker Compose 跑通 FastAPI、PostgreSQL、Redis、Celery Worker/Beat、内部 MCP、MinIO 和 MinerU 的真实文档解析链路，并以 DOCX 与 PDF 两阶段验收结果区分完成口径。

**架构：** FastAPI、Worker、Beat 和 MCP 复用同一个 Python 3.12 后端镜像，PostgreSQL 与 MinIO 使用持久化卷，Redis 只作 Broker。核心 Compose 先用 DOCX 验证真实网络和业务终态，MinerU 作为独立 GPU profile 后接入 PDF；全部业务事实仍写入 PostgreSQL。

**技术栈：** Python 3.12.13、uv 0.12.1、FastAPI、SQLAlchemy 2 async、PostgreSQL 17.6、Redis 7.4、Celery 5.5.3、MCP Python SDK 2.1.0、MinIO、Docker Compose 5.1、MinerU 3.1.0、pytest、Ruff、mypy。

**安全边界：** 不使用或保存用户曾在聊天中发送的旧凭证。联调 Secret 由本地生成器写入被 Git 忽略的 `.env.integration`；只有 `.env.integration.example` 进入仓库。除 FastAPI 本地端口外，不映射 PostgreSQL、Redis、MinIO、MCP 或 MinerU 宿主端口。

```python
@asynccontextmanager
async def _lifespan(_: MCPServer) -> AsyncIterator[McpRuntime]:
    settings = get_settings()
    engine = create_engine(settings.database_url)
    session_factory = create_session_factory(engine)
    http_client = httpx.AsyncClient()
    storage = build_object_storage(settings)
    try:
        yield McpRuntime(
            session_factory=session_factory,
            ingest_service_factory=lambda: _build_ingest_service(
                settings=settings,
                storage=storage,
                http_client=http_client,
            ),
        )
    finally:
        await http_client.aclose()
        await engine.dispose()
```
