# 16 产品版本规划

> 版本：v1.1  
> 更新日期：2026-08-18  
> 文档状态：产品版本方向基线  
> 当前实施版本：V1  
> 上游基线：`11-产品需求文档（PRD）.md` v2.9  
> 关联文档：`09-业务流程与项目状态机.md`、`10-核心业务对象与数据字典.md`、`11-产品需求文档（PRD）.md`、`13-项目决策与工作记录.md`、`15-评估体系与测试计划.md`

## 零、文档定位

本文档用于保存 V1、V2、V3 的产品目标、能力边界、版本依赖和演进顺序，避免后续重新打开项目时遗忘已经确认的版本方向。

本文档不是 V2 或 V3 的正式 PRD：

- V1 范围以当前 PRD 为准，属于当前开发与验收基线；
- V2、V3 只记录已经确认的产品方向，不代表已经完成立项、排期或验收承诺；
- V2、V3 启动前必须分别建立正式 PRD、评估门槛和实施计划；
- 后续版本不能通过修改本文档静默删除 V1 已确认范围。

## 一、版本命名与治理规则

### 1.1 正式产品版本

```text
V1：单项目完整闭环
V2：多场景与团队协同
V3：投标质量运营与平台化
```

正式对外版本不使用 `V1.1`、`V1.2`。

### 1.2 V1 内部里程碑

```text
M1：项目与文件
M2：要求与证据
M3：标书生成与工作台展示
M4：审核、合规与返工
M5：内部交接与版本留痕
M6：评估、修复与交付验收
```

内部里程碑只表示研发顺序，不是可独立对外承诺的产品版本。

### 1.3 版本变更原则

- 当前只实施和验收 V1；
- 总体建设原则为“V1 核心链路做深，V2 扩展业务广度和协同能力，V3 建设质量运营和平台化能力”；
- V1 坚持“场景做窄、核心做深”，用有限场景验证来源、权限、人工关口、状态、版本、失败恢复、审计和证据追溯，不以功能数量代替企业级深度；
- V2、V3 的方向调整必须记录原因和影响；
- 新版本应在上一版本核心闭环稳定后启动；
- 后续版本优先复用 V1 的项目、文件、要求、证据、章节、审核、版本和审计对象；
- 不为后续版本提前建设没有 V1 使用价值的通用平台能力；
- `specs/research` 中早期版本设想仅作历史参考，不覆盖本规划。

## 二、版本总览

| 版本 | 产品定位 | 核心价值 | 当前状态 |
|---|---|---|---|
| `V1` | 单项目标书生成与内部交接工作台 | 跑通从项目输入到标书初稿、审核和内部提交留痕的完整闭环 | 当前实施与验收范围 |
| `V2` | 多场景与团队协同增强版 | 支持更多标书类型、数据来源、协作方式和受控对外版本 | 已确认方向，尚未独立立项 |
| `V3` | 投标质量运营与平台化版本 | 将标书生产数据转化为质量评估、模型回测和跨项目运营能力 | 已确认方向，尚未独立立项 |

## 三、V1：单项目完整闭环

### 3.1 版本目标

> 从输入项目代码到内部提交留痕，跑通单个政府采购信息化服务项目、单个采购包的完整业务闭环。

### 3.2 六项核心工作台能力

1. **任务流程可视化**：展示固定流程阶段、当前状态、负责人、进度、待办和阻断事项；
2. **核心结论集中展示**：集中展示项目事实、时间节点、资格结论、评分项、证据缺口、报价状态、风险和审核状态；
3. **数据证据可查看**：结论可定位到来源文件、页码、原文、企业证据和有效状态；
4. **标书内容可预览**：按章节预览正文、引用、图表、说明材料、风险和生成状态；
5. **审批与合规可闭环**：支持 Agent 预检、结构化问题、人工处理、退回修改、复核关闭和阻断控制；
6. **内部提交和版本可追溯**：形成交接基线、文件清单、版本、哈希、交接人、接收人、时间和审计记录。

### 3.3 V1 端到端范围

```text
输入项目代码
→ 自动获取或人工补充采购文件
→ 确认有效文件版本
→ 提取项目事实、要求、评分项和时间节点
→ 匹配企业证据和简化历史参考
→ 人工确认响应矩阵和报价版本
→ 生成带引用的标书初稿
→ Dashboard 展示任务、结论、证据、风险和进度
→ 预览章节、来源、图表和说明材料
→ Agent 预检
→ 人工审核、退回和结构化修改
→ 关闭阻断问题
→ 冻结内部交接版本
→ 投标递交责任人确认接收
→ 保存版本、文件清单、哈希和审计记录
```

### 3.4 V1 实现深度边界

- 使用固定投标流程，不建设通用 BPMN 工作流引擎；
- 建设一个主要数据连接器或受控模拟连接器，并以人工上传作为正式兜底，不承诺覆盖全国全部采购平台；
- 支持手动刷新或人工补充公告、澄清、更正和补充文件，不建设自动定时监控和临期高频监控；
- 提供少量受控候选的简化历史参考池、差异说明和用途确认，不建设大规模横向分析或中标/未中标归因；
- 接入至少一个受控 Excel 模板或内部报价结果，执行预算、限价、税率、合计、单位和大小写校验，不建设敏感性分析、策略模拟或自动最优报价引擎；
- 提供章节预览和可编辑导出，不建设在线 Office 和多人实时编辑；
- 提供固定角色审核闭环、结构化问题和基础风险豁免，不建设任意配置的通用审批、会签或复杂授权平台；
- 影响分析做到对象级或章节级，无法可靠判断时扩大复核或执行全量复核，不承诺字段级精确影响和自动最小化增量复核；
- 完成内部受控交接、接收确认和简单人工递交记录，不建设动态水印、下载次数和复杂分发策略，不自动执行外部平台递交或 CA 签章。

上述边界只收敛 V1 的场景广度和自动化复杂度，不降低正确性、权限、版本、人工确认、审计、拒答、阻断和可追溯质量底线。

### 3.5 V1 完成条件

- 六项核心工作台能力可以在同一个项目中连续使用；
- `L1` 和 `L2` 通过，达到 V1 技术完成；
- `L3` 通过，完成 V1 软件交付验收并达到试点就绪；
- `L4` 独立验证真实业务价值，不阻塞 V1 软件交付验收；
- 具体门槛以 `15-评估体系与测试计划.md` 为准。

## 四、V2：多场景与团队协同

### 4.1 版本目标

> 将 V1 从“单项目完整可用”扩展为“能够覆盖更多投标场景，并支持团队日常协同和受控对外版本管理”。

### 4.2 计划能力方向

#### 多标书类型

- 项目投标标书；
- 技术方案标书；
- 商务响应标书；
- 投标澄清和补充响应文件；
- 不同类型文件的模板、章节和审核规则。

#### 更多数据接入与持续监控

- 增加招投标平台、采购公告平台和企业系统连接器；
- 持续监控公告、澄清、更正、补遗和关键项目事件；
- 完善连接失败、授权过期和人工兜底管理；
- 支持更多可控的文件同步和更新提醒。

#### 历史项目与模板增强

- 更完整的同类项目横向对比；
- 历史中标和未中标项目分类复盘；
- 行业、项目类型和章节模板管理；
- 参考内容复用效果和人工采纳记录；
- 复用边界、差异项和失效规则增强。

#### 报价策略增强

- 支持更多报价模板和项目类别适配；
- 提供高级报价模型、敏感性分析和策略模拟；
- 保持商务人员最终选择、项目负责人确认和人工风险接受边界；
- 不建设脱离业务规则和人工授权的自动最优报价。

#### 团队协同与审核增强

- 多项目任务、进度和团队协同看板；
- 更灵活的角色、责任和审核路径配置；
- 字段级精确变更影响分析和自动最小化增量复核；
- 跨项目任务负载、截止时间和阻断事项管理；
- 审核问题统计和团队处理效率分析。

#### 客户版与对外版本

- 从内部审核版生成受控客户版或对外版本；
- 隔离内部风险、批注和敏感信息；
- 管理对外版本、接收对象、有效期和更正记录；
- 支持动态水印、下载次数、禁止转发和复杂分发策略；
- 提供受控生成与分发能力，但是否接入外部交易平台需单独评估。

### 4.3 V2 不自动包含

- 投标质量评分和模型回测平台；
- 跨组织规模化运营分析；
- 完整多租户 SaaS；
- 自动外部递交和 CA 签章；
- 所有行业、工程招标和联合体规则。

### 4.4 V2 启动前必须确认

- 优先支持的标书类型；
- 优先接入的平台和企业系统；
- 客户版、对外版和正式递交文件的法律边界；
- 多项目协同的组织和权限模型；
- 审核流程允许配置到什么程度；
- V2 独立验收场景和数据来源。

## 五、V3：投标质量运营与平台化

### 5.1 版本目标

> 将标书编制过程中积累的结构化数据、审核问题和评测结果转化为投标质量、模型能力和团队运营的持续改进平台。

### 5.2 计划能力方向

#### 投标质量评估产品化

- 项目质量评分卡和分域结果；
- 资格、评分、证据、报价、风险、版本和交接质量趋势；
- 团队、项目类型和时间周期对比；
- 末期阻断问题、返工和审核效率分析；
- 质量问题复盘和改进任务。

#### Agent 与模型回测

- Agent、模型、提示词、规则和检索配置版本管理；
- 固定评测集、历史失败集和生产回归集；
- 离线回测、消融实验和版本对比；
- 质量、成本、耗时和稳定性综合分析；
- 新版本灰度、回滚和发布建议。

#### 跨项目知识与运营

- 历史项目复盘和知识沉淀；
- 跨项目要求、证据、风险和模板分析；
- 业务效率、审核质量、人工工作量和成本分析；
- 组织级投标资产和证据治理；
- 项目成功与失败因素的受控分析，不自动等同于中标预测。

#### 平台化与生产级能力

- 多组织、角色、保密等级和用途权限治理；
- 高可用、监控、告警、灾备和容量管理；
- 安全审计、数据生命周期和模型调用治理；
- 更多行业、工程类、多采购包和联合体支持；
- 外部采购平台、CA 签章和递交集成的合规与技术评估。

### 5.3 V3 不自动承诺

- 中标概率预测；
- 替代人工投标决策；
- 未经采购平台和法律合规确认的自动递交；
- 使用小样本直接归因中标率提升；
- 将模型评分直接作为人员绩效结论。

### 5.4 V3 启动前必须确认

- 质量评分是否面向单项目、团队还是组织；
- 模型回测允许使用的数据范围和脱敏规则；
- 生产反馈如何进入训练、规则和评测闭环；
- 多组织部署、租户隔离和商业模式；
- 外部平台集成的授权、责任和审计边界；
- 生产级 SLO、安全和灾备门槛。

## 六、能力演进矩阵

| 能力 | V1 | V2 | V3 |
|---|---|---|---|
| 项目范围 | 单项目、单采购包 | 多项目协同、更多标书类型 | 多组织、复杂项目和跨项目运营 |
| 数据接入 | 有限来源 + 人工兜底 | 更多连接器 + 持续监控 | 企业级集成治理和规模化运行 |
| 历史参考 | 简化参考池和人工确认 | 完整横向对比和模板复用 | 跨项目知识与运营分析 |
| 报价 | Excel 接入、规则校验、人工确认 | 多模板和场景增强 | 质量、成本和策略复盘，不做自动投标决策 |
| 标书生成 | 固定类型、章节预览和导出 | 多标书类型、客户版和对外版本 | 跨组织模板与质量运营 |
| 审核协同 | 固定角色和结构化闭环 | 灵活协同、精细影响分析 | 组织级质量与审核运营 |
| 交接递交 | 内部受控交接、人工递交记录 | 客户版受控分发 | 外部平台和 CA 集成评估 |
| 评估 | L1-L4 研发和验收体系 | 多场景质量数据积累 | 质量评估产品化和模型回测平台 |

## 七、后续版本立项规则

V2 或 V3 正式立项时必须：

1. 明确目标客户和真实业务场景；
2. 从本规划选择能力，不默认全部进入版本；
3. 建立该版本独立 PRD 和非目标；
4. 明确数据来源、权限和人工决策边界；
5. 建立独立验收场景和评估门槛；
6. 评估对 V1 领域对象、状态机和接口的兼容影响；
7. 完成版本范围确认后再进入技术方案和开发计划。

本规划用于防止遗忘和方向漂移，不用于提前承诺尚未验证的交付范围、工期或收益。
