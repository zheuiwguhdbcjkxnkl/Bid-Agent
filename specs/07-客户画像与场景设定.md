# 07 客户画像与场景设定

> 版本：v6.0
> 项目性质：个人主导的企业级场景模拟项目
> 用途：为“投标文件智能编制与合规审核平台”提供具体、自洽、可用于产品设计和面试讲解的业务背景。

## 一、真实性边界

本项目使用真实公开招标文件、真实法规和可复现的技术实现，但公司、人物、内部流程和企业知识库均为脱敏模拟设定。

面试时可以说明自己基于行业调研构造了企业场景，不能把模拟公司、虚构事故、内部试点或团队协作说成真实任职经历。若项目来自真实工作，应使用真实公司和团队信息，并遵守保密要求。

推荐表述：

> 这是我个人主导的企业级场景模拟项目。我调研了信息化集成商的投标流程，使用公开招标文件和明确标注的模拟企业资料，完成招标文件解析、合规审查、响应规划、证据检索和评测闭环。

## 二、项目关系与称谓

本项目同时存在“系统建设项目”和“甲方参与的投标项目”两层业务关系。为避免面试和文档中的“甲方”歧义，统一使用以下称谓：

```text
系统建设项目
乙方：南京知衡智能科技有限公司（模拟的 AI 软件服务商）
  → 交付投标文件智能编制与合规审核平台
甲方：云启智联科技股份有限公司（模拟客户）
  → 在内部投标管理流程中使用该平台

甲方参与的采购项目
采购人/招标人：发布采购需求的一方
云启智联：投标人/供应商
```

除非明确讨论系统建设合同，否则“甲方”均指云启智联；讨论招投标法律关系时，使用“采购人/招标人”和“投标人/供应商”，不再混用“甲方、乙方”。

## 五、甲方业务问题

企业已有招投标平台、采购公告平台、企业知识库、历史标书库、Excel报价模板和审核流程。项目要解决的不是“没有工具”，而是工具和数据之间缺少统一流程。

主要问题包括：

1. 公告、采购文件、补充文件、企业资料、历史标书、报价模型和审核记录分散；
2. 商务指标、Excel 模板、报价假设、公式版本和计算结果缺少统一口径与留痕；
3. 同类项目、历史中标方案和报价候选方案需要反复整理；
4. 标书章节、图表、引用、数据来源、风险提示和说明材料标准不统一；
5. 资格缺口、实质性要求遗漏、评分点未覆盖等合规问题暴露偏后；
6. 文件变更、版本更正、内部交接、递交结果和回执缺少统一闭环；
7. 多人协作中的任务、责任、截止时间、修改范围和审核状态难以统一跟踪；
8. 企业资质、人员、案例和合同材料的有效性、完整性、权限与证明关系难以统一管理；
9. AI 初稿可能缺少事实依据、来源定位和可信审核机制。

项目目标是把重复、标准化、可规则化的工作交给系统，同时保留业务人员对投标策略、报价假设和最终提交的决定权。

## 六、场景来源、采购动机与交付范围

行业调研和公开的投标无效案例表明，人员资格、投标保证金、签章、文件格式、有效期和实质性响应是常见高风险项。企业内部也会出现临近提交才发现材料缺失、引用旧版要求或跨章节数据不一致的情况。

因此，甲方委托乙方建设智能投标辅助系统 V1，目标是从项目编号出发，把数据接入、文件解析、要求抽取、企业证据、同类项目、报价方案、章节生成、风险审核和内部交接串成统一闭环。

V1 聚焦**单个政府采购信息化服务投标项目、单个采购包**，覆盖从项目创建到内部受控交接，并记录投标递交责任人的人工外部递交结果和回执。

V1 实际实现范围：

- 支持通过来源平台和外部项目编号创建项目，公开数据自动获取，受限数据人工上传兜底；
- 支持单个投标项目、单个采购包及其公告、采购文件、澄清/更正文件和企业证据材料；
- 支持同类项目推荐、横向对比、参考项目池和章节级用途确认；
- 支持受控 Excel 模板、报价假设、候选方案、规则校验、模型推荐和人工最终确认；
- 支持从要求抽取、响应矩阵、章节初稿、图表与说明材料到风险审核和内部交接基线；
- 支持项目负责人、商务审核、合规/法务审核、结构化返工和增量复核；
- 支持受控交接给投标递交责任人，并记录人工外部递交状态与回执；
- 支持 PostgreSQL 原生词法检索 + 向量检索、元数据过滤、RRF 融合和有限重排的企业证据检索；要求、评分项、响应章节和证据的已确认关系为 P1 受控 GraphRAG 增强预留；
- 多标包、联合体和工程招标只保留领域模型与异常提示，不在 V1 实现完整业务闭环；
- 不承诺接管所有外部平台，不自动操作 CA、专用客户端或加密环境；
- 不自动完成电子交易平台递交、CA 签章、中标预测或替代人工决策。

这里不虚构某次真实事故或商业损失，演示案例只用于验证系统流程，不对应真实客户和真实投标结果。

## 八、典型甲方投标业务案例

**模拟项目：滨江市大数据管理局政务云平台运维服务采购项目**

- 项目类型：政府采购服务项目；
- 采购方式：公开招标；
- 评审方法：综合评分法；
- 招标文件：168页PDF，包含实质性要求、资格条件、评审因素和技术服务要求；
- 企业资料：使用带`[SIMULATED]`标记的资质、人员、产品和历史案例。

案例中的页数和条款数量用于演示数据设计，不作为项目效果指标。

```text
T-30天  输入来源平台和项目编号
         → 数据连接器获取公开公告和采购文件，受限文件转人工上传

T-28天  上传招标文件和附件
         → 文档解析节点生成章节、表格、页码和版本信息
         → 结构化抽取资格条件、实质性要求、评审因素和时间节点

T-25天  资格与合规审查Agent比对企业知识库
         → 发现CMMI三级评估结果临近有效期，需要人工核验投标截止日是否有效

T-20天  响应规划Agent生成投标文件目录、章节任务和证据需求
         → 推荐同类项目并由投标经理确认参考项目池和章节用途

T-18天  商务人员使用受控 Excel 模板形成报价候选方案
         → 规则排除无效方案，大模型解释差异，商务人员选择并由项目负责人确认

T-15天  评分点覆盖Agent检查评分项与响应章节、证明材料的映射
         → 发现同类项目业绩评分项缺少验收材料

T-10天  一致性审查Agent检查跨章节信息
         → 发现商务响应与技术方案中的项目负责人姓名不一致
         → 根据招标文件判断其影响，并提交人工复核

T-5天   风险复核Agent汇总投标无效风险、证据缺口和待确认事项
         → 项目负责人、商务审核和合规/法务按角色复核，问题结构化返工

T-0     冻结内部交接基线并受控交接给投标递交责任人
         → 递交责任人人工完成外部递交，系统记录平台、时间、状态和回执
```

## 九、系统目标与评测口径

### 业务目标

- 缩短招标文件首次阅读和要求整理时间；
- 优先保证高风险实质性要求的召回；
- 所有风险结论能够定位到文件、页码和原文；
- 在提交前发现证据缺失、版本过期和跨章节冲突；
- 保留人工确认和修改记录。

### 技术指标

- 实质性要求识别Precision、Recall和F1；
- 资格条件与评审因素抽取准确率；
- 证明材料匹配准确率和证据覆盖率；
- 引用正确率和无证据拒答率；
- 跨章节冲突检测准确率；
- Agent成功率、重试率和人工接管率；
- 单份文件端到端处理时间。
- 平台查询和文件自动获取率；
- 首稿生成时间、人工查找整理时间和确认事项数量；
- 平均审核时间、退回轮次和增量复核比例；
- 来源可追溯率、版本失效正确率和未解决阻断风险数。

指标数值必须来自实际评测报告。项目完成前只能说明目标，不能提前声称“零漏判”“已上线”或“效率提升多少”。
