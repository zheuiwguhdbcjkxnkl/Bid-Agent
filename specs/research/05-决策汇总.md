## 1. 场景决策（D1/D2）

**推荐**：主攻「招标文件智能解读 + 废标条款识别」（多智能体项目）与「招标文件 RAG 问答」（RAG 项目），引用 195 号文场景命名。

**理由**：
- 政策风口：国家发改委等 8 部门 2026-02 印发《关于加快招标投标领域人工智能推广应用的实施意见》（发改法规〔2026〕195 号），明确「投标合规自查」「投标策划」两大 AI 场景，2026 年底部分省市全覆盖 → 简历项目有官方背书（01 文档，官网源）。
- 竞争判断：标讯聚合（大平台数据壁垒）、评标/清标系统（上市大厂+监管+信创）个人不可触碰；AI 标书生成工具已拥挤（智标/标探长/易标/文兜 10+ 款）但**质量参差、无头部、少开源可复现方案**——「小而尖」可打。
- 数据可得：招标文件全公开（02 文档实测），产出可验证（废标点清单、条款原文引用），评估客观（01 文档 6.1 表）。

**不做**（Non-Goals）：不做实时全网标讯聚合、不做评标/清标系统、不做「3 分钟生成 20 万字」营销噱头（质量不可控）。

## 2. 数据源决策（D3）

**主选**：CCGP（中国政府采购网，政府采购全量）+ GGZY（全国公共资源交易平台，工程建设）双主源；江苏省级平台（苏采云体系）为全文语料补充。

**理由**（02 文档实测）：
- 公告全文 100% 公开免登录；CCGP 字段结构化（含预算金额/联系人/开标时间）；GGZY 正文页静态可抓；两者均无 robots 禁令。
- 招标文件全文三类可得性：A 附件直链公开（江苏已实测 156KB .doc 免登录直下）→ B 注册供应商账号免费下载 → C 需 CA/付费（绕行）。**A/B 通道已实测可行，RAG 语料有保障**。

**备用/排除**：
- CEBP（中国招标投标公共服务平台）：**robots.txt 实测 `Disallow: /`，合规红线，仅人工检索 + 参考其公开的《招标公告和公示数据接口规范》**（rar 已下载存 `_evidence/bulletin-info.rar`）。
- 军队采购网：数据敏感，不用。
- 商业 API（剑鱼/千里马）：价格未公开[单源⚠️]，预算+简历展示双原因不买。

**采集目标**：500-1000 条公告、200-300 份招标文件；历史回填 CCGP 按年月归档可行；GGZY 列表 JS 需逆向[待核验]。

## 3. 架构决策（D4/D5/D6/D7/D8/D9/D10/D12）

### 总体架构：一库两项目，RAG 即工具

```
┌─────────────────────────────────────────────────────────────┐
│ 应用层  Streamlit 多页（标讯浏览/解析预览/废标检测/撰写工作台/RAG问答）│
├─────────────────────────────────────────────────────────────┤
│ 项目① 多智能体：LangGraph Orchestrator + 5 子Agent            │
│   解析→废标识别→资质提取→撰写→质检（质检=差异化亮点）              │
│   工具调用：rag_query / sql_query / doc_parse / file_write    │
├─────────────────────────────────────────────────────────────┤
│ 项目② RAG 问答：V1 纯向量（BGE-M3+Chroma+Rerank）             │
│              V2 向量+图（LightRAG 双通道，对比实验）            │
├─────────────────────────────────────────────────────────────┤
│ 共享底座：采集(CCGP/GGZY/江苏)→解析(PyMuPDF/MinerU/OCR)        │
│          →SQLite+FTS5 / Chroma →评测集+RAGAS                  │
├─────────────────────────────────────────────────────────────┤
│ LLM 适配层：DeepSeek-V3 主力 | GLM-Flash 免费兜底 | Qwen 本地可选│
└─────────────────────────────────────────────────────────────┘
```

### 模块决策明细

| 模块 | 推荐 | 为什么不用 X |
|------|------|-------------|
| 编排框架 | **LangGraph**（MIT） | CrewAI 黑盒委托难采集指标（本项目卖点是量化评测）；AutoGen License 非标准+API 变动；自研 DeepA2A 时间成本高（可降级为对照实验） |
| 子 Agent | Orchestrator + 解析/废标识别/资质提取/撰写/质检 | ⑤质检形成「生成-自检」闭环，天然产出评测指标 |
| 文档解析 | PyMuPDF（文本型快通道）+ MinerU（复杂版式/扫描件）+ PaddleOCR 兜底 | Docling 中文生态弱于 MinerU（留 20 份样本对照）；marker 中文表格一般 |
| 长文档切分 | 结构感知（目录/标题层级），主块 800-1000 token、overlap 100-150，表格独立成块 | 招标文件动辄上百页，固定切分破坏语义 |
| 结构化存储 | SQLite + FTS5（中文全文检索） | Postgres 需维护服务，个人项目不值 |
| 向量库 | Chroma（本地文件、零运维、元数据 where 过滤） | FAISS 无元数据过滤（招标需按来源/地区/时间过滤）；Milvus 重；10 万+ chunk 再迁 Qdrant |
| Embedding | **BGE-M3**（8192 token，dense+sparse+colbert） | text2vec/bge-zh 512 token 上限是硬伤，长条款/评分细则强切破坏语义 |
| Rerank | bge-reranker-v2-m3 本地必加（top50→top5-8） | 废标条款/资质是精确召回场景，RAGAS context_precision 前后对比=简历量化点 |
| LLM | DeepSeek-V3 主力（¥1.6/百万输入、128K）+ GLM-4.7-Flash 免费兜底 | 本地 Qwen2.5-7B/14B 结构化抽取质量明显低于 API，仅演示 |
| 图RAG | V1 纯向量打基线 → V2 LightRAG（MIT，图+向量双通道） | MS GraphRAG 社区报告生成重、LLM 成本高、中文一般；Neo4j 仅可选 |
| 界面 | Streamlit 5 页 | Gradio 表单工作流弱；纯前端不需要 |
| 评测 | RAGAS（Faithfulness/Context Precision/Context Recall/SS）+ 自建 30-50 条 + 废标 F1≥0.90 / 资质 F1≥0.85 | 评测先行，所有模块决策用指标说话 |

**明确不碰**：QAnything（停更+AGPL）、DeepAgents/open-rag（**仓库实测 404，别写进简历**）、zhaobiao_spider（停更 6 年）、Gitee Java 栈平台（wzh/招投标，仅参考业务模型）。
