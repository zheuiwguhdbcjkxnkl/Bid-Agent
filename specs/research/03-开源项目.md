# 03-开源项目调研：招投标方向可复用开源生态

> **调研日期**：2026-08-17
> **调研范围**：文档结构化解析 / RAG 框架 / 多智能体编排 / 招投标垂直项目 / 标讯爬虫
> **数据来源**：GitHub API（gh CLI 认证查询，星数/License/最近 commit 为实测值）、Gitee 搜索实测、项目 README 深读、Jina Reader 抓取中文社区
> **来源标注规范**：`[GitHub API]` = 官方 API 实测；`[WebSearch]` = 搜索引擎/网页抓取；`[单源⚠️]` = 单一信源未交叉验证；`[待核验]` = 存在矛盾或未能核实
> **面向用户**：AI/NLP 教师，技术栈 LangChain + Chroma + BGE + Qwen，有 RAGAS 评估经验

---

## 0. 结论速览（TL;DR）

1. **招投标垂直开源生态处于"工具多、平台少、无标准件"状态**：GitHub/Gitee 上已有 20+ 个直接相关项目，但大多数是 ⭐0-30 的个人作品；唯一有规模的是 **OpenBidKit_Yibiao（易标，⭐2.4k，含废标项检查）**。
2. **"招标文件结构化解析 / 废标条款识别"没有成熟的通用开源库**——最接近的是 OpenBidKit 的废标项检查、BidMaster-Pro 的 21 项合规检查、jiujiujiu/bid_review（清标/废标项检查，0⭐）。**这正是一个可写进简历的差异化空白点**。
3. **用户技术栈（LangChain + Chroma + BGE + Qwen）与主流生态完全对齐**：LangGraph 是目前最适合做 Orchestrator+子Agent 的编排框架（MIT）；MinerU/Docling 负责招标文件解析；RAG 评估用 RAGAS（用户已有经验）。
4. **最值得 fork/借鉴的三个垂直项目**：`FlyingJackLee/bid-agent`（LangGraph 分层架构，与用户选型完全同构）、`BidMaster-Pro`（21 项合规检查 + MinerU + ChromaDB，功能清单可抄）、`hysios/zhaobiao`（《招标投标法》152 条向量化逐页合规审查，RAG 原型可直接参考）。
5. **License 红线**：AGPL-3.0 项目（OpenBidKit、BidMaster-Pro、QAnything、PyMuPDF）用于**简历演示/教学无碍，但商用需谨慎**；MinerU/FastGPT/Dify 的 License 均为非标准声明，**商用前必须人工核验**（详见待核验清单）。

**各层"谁最擅长什么"一句话版**：
- **解析**：MinerU 中文复杂版面最强；Docling 全面且 License 干净；pymupdf4llm 做轻量教学 demo 最快。
- **检索**：RAGFlow 开箱即用（含解析+前端）；LangChain+Chroma 灵活可定制（用户已有）；LightRAG 提供向量+图双通道。
- **编排**：LangGraph 状态机适合"解析→识别→撰写→审查"流水线，天然支持人工介入（interrupt）。
- **前端/产品**：OpenBidKit（Electron 桌面）、BidMaster-Pro（桌面+服务端+Docker）、RAGFlow/FastGPT/Dify（Web 平台）——若要完整产品形态，直接部署这些比自研快。

## 4. 特别关注：招标文件结构化解析 / 废标条款识别有现成开源吗？

**结论：基本没有成熟通用开源方案，属于"半空白"领域——这是机会。**

核实过程与证据：
1. **GitHub 中文搜索**（招标/标书/招投标/招标文件解析/废标/清标，`gh search repos` 实测）：
   - 直接命中 15+ 个垂直项目，但 ⭐≥100 的只有 OpenBidKit_Yibiao（⭐2.4k）和 open-tender-watch（⭐104, Ruby/EU 场景）。
   - 废标/清标关键词在 GitHub 上**无独立知名项目**（结果被无关大仓库污染，无有效命中）。
2. **Gitee 搜索实测**（so.gitee.com，"废标"仅 6 个结果）：唯一对口的两个是 `jiujiujiu/bid_review`（清标/废标项检查，0⭐，Python，2026-07）和 OpenBidKit 镜像（废标项检查是其功能之一）。
3. **垂直工具中的实现**：废标相关能力目前都**内嵌**在整体工具里而非独立库——
   - OpenBidKit_Yibiao：废标项检查（规则深度未核验 [待核验]）；
   - BidMaster-Pro：21 项合规检查 + 招标解读阶段"标记潜在废标风险点"；
   - hysios/zhaobiao：按《招标投标法》逐页审查（❌违规/⚠️风险/✅合规），可视为"废标条款识别"的 RAG 版实现。
4. **中文社区信源**（掘金搜索 [WebSearch]）：2025 年以来以商业产品（如"慧中标AI智能标书"）推广为主，未见成熟开源解析库的分享文章。

**对用户的意义**：简历项目若做"招标文件结构化解析（资质要求/评分标准/废标条款抽取）+ 废标条款识别"，就是站在 OpenBidKit/BidMaster 的实践之上、又比它们更聚焦/更可评估（RAGAS 评估）的原创点。建议在简历中如实写"调研了开源生态（OpenBidKit/BidMaster-Pro 等），现有方案为整体工具内嵌规则，无通用可评估的独立库，本项目自研 + RAGAS 量化评估"——这本身就是技术判断力的体现。
