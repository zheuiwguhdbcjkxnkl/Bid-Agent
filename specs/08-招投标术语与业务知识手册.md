# 08 招投标术语与业务知识手册

> 版本：v2.2
> 用途：建立项目统一的招投标领域语言，并把业务概念映射到多智能体、RAG和审核模块。
> 使用原则：每个术语必须说明适用制度；系统内部优先使用规范术语，行业口语只作为同义词或搜索词保留。

## 一、制度范围

本项目同时参考两类场景，但第一版主要聚焦 **政府采购信息化服务项目**：

1. **政府采购货物和服务**：主要使用《政府采购法》及其实施条例、政府采购货物和服务招标投标管理办法；竞争性磋商、竞争性谈判、询价等属于政府采购方式。
2. **依法必须招标的工程建设项目**：主要使用《招标投标法》及其实施条例；公开招标、邀请招标、评标委员会、否决投标等术语更常见。

政府采购工程进行招标投标的，适用《招标投标法》；政府采购货物、服务以及采用非招标方式采购的工程，主要适用政府采购法律制度。系统设计时必须给文件标注制度和项目类型，不能把两套规则混成一套。

## 二、参与方与角色

| 术语 | 适用范围 | 含义 | 项目中的对应角色 |
|---|---|---|---|
| 采购人 | 政府采购 | 使用财政性资金采购货物、服务或工程的单位 | 需求来源、采购文件确认方 |
| 招标人 | 招标投标 | 提出招标项目、编制招标文件并组织招标的主体 | 工程或企业招标的需求方 |
| 采购代理机构 | 政府采购 | 接受采购人委托组织采购活动的机构 | 公告、文件和流程协助方 |
| 招标代理机构 | 招标投标 | 接受招标人委托办理招标事宜的机构 | 工程招标流程协助方 |
| 供应商 | 政府采购 | 向采购人提供货物、服务或工程的法人、组织或个人 | 云启智联作为甲方客户时，在政府采购项目中以供应商身份参与 |
| 投标人 | 招标投标 | 响应招标并参加投标竞争的法人或其他组织 | 云启智联作为甲方客户和系统主要使用方，在招标投标项目中以投标人身份参与 |
| 评审专家 | 政府采购 | 参与政府采购项目评审的专家 | 真实评审不由本系统执行 |
| 评标委员会 | 招标投标 | 依法组建、负责评标的组织 | 系统只模拟其关注的评审因素 |
| 采购评审小组 | 政府采购 | 按采购方式组织采购项目评审的人员 | 系统不替代其作出成交决定 |

注意：同一个组织在不同语境中可能是采购人、招标人或投标人。系统中应从项目上下文确定角色，不能仅根据公司名称判断。
### 项目交付关系说明（非招投标法律关系）

本手册的招投标术语服务于 `07-客户画像与场景设定.md` 所定义的业务场景：云启智联是**系统建设项目的甲方客户**，也是其参与采购项目时的**投标人/供应商**；南京知衡智能科技是**系统建设项目的乙方交付方**，不以投标人身份参与该采购项目。

因此，“甲方/乙方”只用于说明软件建设与交付关系；在招投标法律关系中，统一使用“采购人/招标人、采购代理机构/招标代理机构、供应商/投标人”等规范术语。系统的数据模型必须分别保存 `delivery_party_role` 与 `procurement_party_role`，不得用一个角色字段混合表达两类关系。

## 三、采购与招标方式

| 术语 | 适用范围 | 含义 | 系统关注点 |
|---|---|---|---|
| 公开招标 | 政府采购/招标投标 | 通过公告向不特定主体发出邀请 | 识别公告、获取文件、投标截止时间和资格要求 |
| 邀请招标 | 政府采购/招标投标 | 向特定供应商或投标人发出邀请 | 识别邀请范围和资格条件 |
| 竞争性磋商 | 政府采购 | 采购人与供应商就技术、服务和价格等进行磋商后提交响应文件 | 识别磋商文件、响应文件、最终报价和综合评分因素 |
| 竞争性谈判 | 政府采购 | 谈判小组与供应商进行谈判，供应商按要求提交最终报价 | 识别谈判文件、技术响应、最终报价和成交规则 |
| 询价 | 政府采购 | 对规格标准统一、现货充足且价格变化幅度小的货物进行询价 | 识别报价要求和供应商响应 |
| 单一来源采购 | 政府采购 | 在符合法定条件的情况下向唯一供应商采购 | 识别唯一性理由和审批材料 |
| 资格预审 | 招标投标/部分采购项目 | 在投标前先审查潜在投标人的资格 | 解析资格预审公告和资格预审文件 |
| 资格后审 | 招标投标/部分采购项目 | 在接收投标后再审查投标人资格 | 识别资格审查表和证明材料 |

“竞争性磋商”和“竞争性谈判”不应写成“招标人和供应商协商”，更准确的表达是“采购人或采购代理机构组织采购活动，与供应商进行磋商或谈判”。

一个采购项目可能拆分为多个标段、标包或包组，投标人可以只投其中一个：

| 术语 | 含义 | 系统关注点 |
|---|---|---|
| 标段 | 工程招标中按空间或专业划分的独立招标单元 | 识别可投范围与标段组合 |
| 标包/包组 | 政府采购中按货物或服务类别划分的采购单元 | 识别包件编号、资格与报价要求 |

V1 聚焦单个标包（对应 `bid_package.is_v1_primary=true`），多标包只保留领域模型与风险提示，不实现各自独立的编制与提交闭环。

## 四、文件体系

| 术语 | 含义 | 系统处理方式 |
|---|---|---|
| 招标公告 | 公开发布的招标项目信息 | 作为公告层RAG语料 |
| 资格预审公告 | 邀请潜在投标人参加资格预审的公告 | 识别资格预审入口和时间节点 |
| 采购文件 | 政府采购项目使用的招标文件、谈判文件、磋商文件、询价通知书等文件的统称 | 根据采购方式选择解析模板 |
| 招标文件 | 招标人向投标人提供的文件，通常包含投标人须知、评标办法、合同条款、技术需求和投标文件格式 | 主要解析对象 |
| 投标人须知 | 说明投标程序、文件要求、时间节点和重要规则的章节 | 高优先级结构化抽取 |
| 投标人须知前附表 | 对投标截止时间、保证金、有效期等项目参数进行集中说明的表格 | 作为时间和硬性参数锚点 |
| 评标办法/评审方法 | 说明如何进行资格审查、符合性审查和评分 | 抽取评审因素、分值和计算规则 |
| 技术需求书/采购需求 | 描述服务范围、技术规格、交付要求和验收要求 | 抽取需求、响应项和证据要求 |
| 响应文件 | 政府采购供应商针对采购文件提交的文件 | 政府采购语境优先使用 |
| 投标文件 | 投标人针对招标文件提交的文件 | 招标投标语境优先使用 |
| 澄清文件 | 对采购文件或招标文件中疑问、歧义的正式说明 | 与原文件建立版本关系 |
| 更正公告 | 对公告或采购文件内容进行正式修改的公告 | 触发版本更新和重新审查 |
| 补遗书 | 工程招标中常见的招标文件补充或修改文件 | 与招标文件建立版本关系 |
| 中标公告/成交公告 | 公开发布中标或成交结果的公告 | 作为结果层RAG语料 |
| 中标候选人公示 | 确定中标人前公布候选人及相关信息的公示 | 支持结果查询和历史案例检索 |
| 中标通知书 | 招标人或采购人向中标人发出的正式通知 | 作为投标结果和合同流程节点 |

澄清、更正和补遗文件必须按发布时间和版本建立关联。最新文件可能改变截止时间、技术参数、评分因素或证明材料要求，不能只把它们作为普通附件检索。

“商务标、技术标、报价标”是部分项目对投标文件内容的组织方式，不是所有项目都采用三标分离，也不代表所有电子招标项目都有独立密封和开标顺序。

## 五、资格、要求与证明材料

| 术语 | 含义 | 系统建模方式 |
|---|---|---|
| 资格条件 | 判断供应商或投标人能否参与项目的准入条件 | `qualification_requirement` |
| 法定资格证明 | 营业执照、行政许可、行业资质等证明材料 | `qualification_evidence` |
| 认证与能力证明 | ISO认证、CMMI评估结果、软件著作权等材料 | 不默认视为法定资质 |
| 业绩要求 | 对历史项目数量、金额、类型、完成时间等提出的要求 | 关联历史案例和验收材料 |
| 人员要求 | 对项目负责人、技术人员资格、经验或社保关系提出的要求 | 关联人员简历、证书和证明材料 |
| 联合体投标 | 两个或多个法人或组织组成联合体共同投标 | 解析联合体协议及成员责任 |
| 投标保证金 | 投标人按文件要求提交的投标担保 | 校验金额、方式、截止时间和凭证 |
| 履约保证金 | 中标后为保证履行合同提交的担保 | 与投标保证金区分阶段 |
| 实质性要求 | 文件明确要求必须满足，或不满足会导致投标无效、否决投标或其他明确后果的要求 | 最高风险标签 |
| 评审因素 | 用于对合格响应进行比较和评分的因素 | `evaluation_factor` |
| 评分项 | 评审因素下可量化的分项及其分值 | `scoring_item` |
| 证明材料 | 用于证明资格、业绩、人员能力或评分依据的文件 | `evidence` |
| 正偏离 | 响应内容优于技术需求或评审要求 | 只有评审标准明确加分时才产生额外得分 |
| 负偏离 | 响应内容低于技术需求或评审要求 | 是否扣分或导致无效，必须以文件规定为准 |

CMMI和ISO不能统一写成“资质等级”。项目中建议区分“法定资格条件”“认证与能力证明”“业绩证明”和“评审因素”。CMMI更适合描述为“CMMI三级评估结果”或“能力成熟度评估结果”，并检查其在投标截止日是否仍然有效。

`★`号、黑体、下划线等版面标记只能作为识别特征，不能单独证明条款具有实质性后果。系统应优先寻找“未满足将导致投标无效”“不响应将被否决”等明确表述，以及资格审查表和符合性审查表中的对应项。

补充：以下概念在投标合规审查中高频出现，需掌握其含义与项目边界：

| 术语 | 含义 | 系统处理方式 |
|---|---|---|
| 围标 | 多个投标人相互串通、操纵中标结果 | 系统不做检测（见第九节） |
| 串标 | 投标人与招标人、代理机构或评审专家串通 | 系统不做检测 |
| 陪标 | 安排关联方“陪衬性”投标，属围标的一种表现 | 系统不做检测 |
| 暗标评审 | 技术标匿名评审，正文不得出现投标人名称、标识等身份信息 | 作为格式/一致性审查规则：身份信息自查 |
| 最高投标限价/招标控制价 | 招标人设定的报价上限，超过即废标 | 作为金额类实质性要求抽取 |
| 投标有效期 | 投标报价承诺的有效天数，需覆盖开标至定标期间 | 作为时间节点类要求抽取 |

## 六、评审与结果

| 术语 | 含义 | 项目边界 |
|---|---|---|
| 初步评审/初步审查 | 对形式、资格和响应性等进行基础审查 | 系统重点支持 |
| 详细评审 | 按评标办法对技术、商务和价格等进行比较评分 | 系统只做评分项覆盖，不代替专家评分 |
| 综合评分法 | 对技术、商务、价格等因素按评审标准综合打分 | 抽取评分项、分值、证据和计算规则 |
| 经评审的最低投标价法 | 在满足实质性要求的投标中比较评审后的价格 | 不预测最终排名 |
| 评标基准价 | 根据具体项目评标办法确定价格评分基准 | 不使用统一公式，按文件抽取 |
| 澄清说明 | 对投标文件中的含义不明确或计算错误进行说明 | 不得借此实质性改变投标文件内容 |
| 投标无效 | 政府采购语境下，某一供应商的投标不符合规定，不能进入正常评审 | 输出投标无效风险 |
| 否决投标 | 招标投标语境下，评标委员会依据招标文件和法律规定否决某一投标 | 输出否决投标风险 |
| 废标 | 政府采购项目整体终止，例如符合条件的供应商不足、报价超过预算或采购任务取消 | 与单个供应商投标无效区分 |
| 中标候选人 | 评标后按照评标结果推荐的候选对象 | 支持结果查询，不预测候选人 |
| 定标 | 招标人或采购人按照规定确定最终中标人或成交供应商 | 不由系统自动决定 |

评审委员会或评审小组的真实评审不由本系统执行。系统输出的是“要求覆盖、证据完整性、风险提示和待人工确认事项”。

评标基准价没有跨项目统一公式。工程项目和政府采购项目可能采用不同评标办法，系统必须先识别制度、采购方式和评审方法，再选择对应的抽取模板。

## 七、系统模块与术语映射

系统由乙方交付给甲方后，服务于甲方内部的投标准备、材料管理和审核流程。平台从甲方获取公告、采购文件、澄清/更正文件及已授权的企业知识资料开始处理；输出仅供甲方内部编制、复核和留痕使用，不代表采购人、代理机构或评审专家作出任何决定。

| 系统模块 | 领域概念 | 输出 |
|---|---|---|
| 文档解析节点 | 采购文件、招标文件、澄清、更正、补遗 | 章节、表格、页码、版本和来源 |
| 资格与合规审查Agent | 资格条件、实质性要求、证明材料、投标无效/否决风险 | 条款判断、证据缺口和原文引用 |
| 响应规划Agent | 投标文件/响应文件、技术需求、章节任务 | 响应目录、任务分配和写作要求 |
| 评分点覆盖Agent | 评审因素、评分项、响应章节、证明材料 | 评分项—章节—证据映射和覆盖率 |
| 一致性审查Agent | 版本、人员、日期、金额、参数和案例 | 跨章节冲突及其来源 |
| 风险复核Agent | 投标无效、否决投标、材料过期、版本失效 | 风险等级、待确认事项和处理建议 |
| RAG问答 | 公告、采购文件、招标文件、中标公告、更正公告 | 带文件、页码、版本和原文引用的回答 |
| 轻量留痕 | 版本号、操作记录、人工确认、提交状态 | 可追溯的内部审查记录 |

## 八、项目标准业务流程
以下流程描述的是**甲方作为投标人/供应商**参与采购项目的业务流程，不是系统建设项目的实施流程。平台通常从“获取采购文件”或“创建投标项目”开始介入，并在提交前输出供人工确认的材料、风险与审查记录。

### 政府采购信息化服务项目

```text
公告发布
→ 获取采购文件
→ 供应商资格判断
→ 解析采购需求和评审方法
→ 准备响应文件与证明材料
→ 初步审查和评分项覆盖检查
→ 人工确认
→ 提交响应文件
→ 评审、成交公告和合同流程
```

### 工程或依法必须招标项目

```text
招标公告/资格预审公告
→ 获取招标文件
→ 资格预审或资格后审
→ 编制投标文件
→ 初步评审和详细评审
→ 推荐中标候选人
→ 定标/中标通知书
→ 合同签订
```

## 九、面试时的专业表述

### 问：系统是不是在预测中标？

答：不是。系统只做招标文件解析、资格和实质性要求检查、评审因素覆盖、证据匹配和版本一致性审查，不预测评委主观评分和最终中标结果。

### 问：系统怎么判断一条要求是否高风险？

答：先识别明确的强制性后果和资格审查表，再结合实质性要求、符合性审查项和证明材料要求；`★`号、黑体等版面特征只作为辅助信号，最后输出原文和待人工确认事项。

### 问：废标和投标无效有什么区别？

答：在本项目中，政府采购语境下用“投标无效”描述单个供应商的响应问题，用“废标”描述采购项目整体终止；工程招标语境下更多使用“否决投标”。系统内部会分别建模。

### 问：正偏离是不是一定加分？

答：不是。只有评审标准明确设置加分时，正偏离才会增加得分；负偏离是否扣分或导致投标无效，也要回到具体采购文件判断。

### 问：系统能检测围标、串标吗？

答：不做。围标串标检测需要跨投标人、跨项目的全量报价、关联关系和投标行为数据，属于监管侧能力，单方投标人项目拿不到这类数据。我的系统聚焦“单方合规自查”——把招标文件里的废标条款、实质性要求、格式和暗标风险查清楚，这是投标人自己能控制的合规边界。

### 问：暗标项目怎么处理身份信息泄露？

答：暗标要求技术标匿名，正文不能出现投标人名称、标识、人员姓名等身份信息，一旦泄露就废标。我把“身份信息自查”做成格式审查规则，扫描正文中的公司名、商标、人名，命中即标记为高风险格式问题，交由人工确认。

## 十、法规与资料阅读顺序

1. 《中华人民共和国政府采购法》：重点看采购方式、废标、合同和政府采购工程的适用范围；
2. 《政府采购货物和服务招标投标管理办法》：重点看资格条件、评审因素、综合评分法和投标无效；
3. 《政府采购竞争性磋商采购方式管理暂行办法》：重点看磋商流程和综合评分；
4. 《中华人民共和国招标投标法》：重点看招标文件、串通投标、评标委员会、否决投标、中标通知书和合同；
5. 《招标投标法实施条例》：补充资格审查、评标、澄清、异议和投诉等流程规则；
6. CCGP、GGZY和省级交易平台的真实公告、采购文件、澄清公告和中标公告。

重点法条索引：

- 《招标投标法》第十九条：招标文件应载明技术要求、资格审查标准、评标标准和方法等；
- 《招标投标法》第三十二条：禁止投标人相互串通投标以及投标人与招标人串通投标；
- 《招标投标法》第三十三条：禁止低于成本竞标、借用他人名义投标和弄虚作假；
- 《招标投标法》第四十二条：评标委员会可以否决所有投标的相关情形；
- 《政府采购法》第四条：政府采购工程进行招标投标的，适用招标投标法；
- 《政府采购法》第三十六条：政府采购项目废标的情形。

## 十一、项目内的规范词表

| 推荐词 | 不作为核心词的说法 | 原因 |
|---|---|---|
| 投标无效 | 废标某家公司 | “废标”通常描述采购项目整体终止 |
| 否决投标 | 评委把标书废掉 | 工程招标中使用规范术语 |
| 实质性要求 | ★号条款 | 星号只是版面信号，不等于法律后果 |
| 评审因素 | 评分标准 | “评审因素”更适合结构化字段 |
| 证明材料 | 企业资质 | 资质、认证、业绩、人员材料需要区分 |
| 更正/澄清文件 | 补充材料 | 需要区分正式文件类型和版本关系 |
| 响应文件 | 标书 | 政府采购语境中更准确 |
| 投标文件 | 标书 | 招标投标语境中更准确 |

## 附录：招投标基础概念速览（投标人视角 · 入门补充）

> 本附录为入门速览，与正文规范术语配合使用；冲突时以正文「项目内规范词表」为准。

### 附录 1 什么是招标 / 什么是投标

- **招标**：招标人（买家：政府/国企/事业单位/企业）公开发布需求与规则，邀请潜在供应商前来竞争的程序。
- **投标**：投标人（卖家：供应商/承包商/服务商）按招标文件要求编制并递交投标文件，参与竞争的程序。
- 两者构成「招标投标」制度：核心是公开、公平、公正、诚实信用。
- 生活类比：装修时业主发需求书（招标），装修公司交方案报价（投标），业主按评分规则选中一家（评标定标）。

### 附录 2 投标全流程（9 步）

```
①找标讯 → ②获取招标文件 → ③解读招标文件 → ④投标决策 → ⑤编制投标文件
                                                              ↓
⑨签约/履约 ← ⑧中标通知 ← ⑦评标定标 ← ⑥递交/开标
```

| 步骤 | 做什么 | 核心产出 |
|------|--------|---------|
| ① 找标讯 | 订阅招标公告，筛选符合资质的项目 | 候选项目清单 |
| ② 获取招标文件 | 报名、下载（可能付费/注册） | 招标文件 PDF/Word |
| ③ 解读招标文件 | 提取资格要求、评分办法、废标条款、工期报价约束 | 需求清单 |
| ④ 投标决策 | 评估竞争、报价水平、中标概率 | 投/不投决策 |
| ⑤ 编制投标文件 | 按评分点撰写商务/技术/报价三部分 | 投标文件 |
| ⑥ 递交/开标 | 按时递交，公开开标唱标 | 开标记录 |
| ⑦ 评标定标 | 专家按评分办法打分，推荐中标候选人 | 评标结果公示 |
| ⑧ 中标通知 | 中标公告、中标通知书、签合同 | 中标通知书 |
| ⑨ 签约履约 | 签约、履约、验收 | 合同 |

### 附录 3 招标文件结构（买家的考题+规则）

| 章节 | 内容 | 重要性 |
|------|------|--------|
| 招标公告 | 项目名称、预算、资格要求、获取方式 | 决定能否投 |
| 投标人须知 | 时间节点、保证金、格式要求、否决投标条款 | 规则核心 |
| 资格要求 | 资质证书、业绩、人员、财务状况 | 门槛 |
| 采购需求/技术要求 | 参数、服务内容、技术标准 | 技术标响应对象 |
| 评标办法 | 综合评分法或最低价法 | 决定怎么拿分 |
| 合同条款 | 付款、验收、违约 | 决定能否干 |
| 投标文件格式 | 目录、盖章、装订要求 | 格式错=废标 |

### 附录 4 投标文件结构（卖家的答卷，「三标」）

| 部分 | 内容 | 对应项目模块 |
|------|------|-------------|
| 商务标 | 投标函、授权书、营业执照、资质证书、业绩、财务报表、保证金 | 资格合规审查 Agent |
| 技术标 | 技术方案、实施方案、人员配置、进度计划、服务承诺、质量保障 | 响应规划/评分覆盖 Agent |
| 经济标 | 投标报价表、分项报价、报价说明 | 报价测算（V1 导入） |

核心要求：**实质性响应**招标文件——每个评分点有对应内容，关键条款明确响应（满足/优于/偏离）。

### 附录 5 关键术语速查（行业口语 vs 规范术语）

| 行业口语 | 规范术语（正文词表） | 一句话含义 |
|----------|---------------------|-----------|
| 废标某家公司 | 投标无效 / 否决投标 | 单个投标人被淘汰；「废标」保留给项目整体终止 |
| ★号条款 | 实质性要求 | 必须实质响应，否则投标无效 |
| 评分标准 | 评审因素 | 决定怎么拿分的结构化字段 |
| 企业资质 | 证明材料 | 资质、认证、业绩、人员材料需区分 |
| 补充材料 | 更正/澄清文件 | 需区分正式文件类型和版本关系 |
| 标书 | 响应文件 / 投标文件 | 政府采购/招标投标语境分别用词 |
